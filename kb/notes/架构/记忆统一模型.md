一句话摘要：双层 MD 知识库是本系统**唯一的持久记忆载体**，承载规范/知识/经验/规划/sub-agent 等一切跨会话记忆；「上下文组装」只是**读取**双层 MD 的方式，绝不能演变成第二个记忆系统。本文定义记忆分类、双链边界与组装三条铁律，作为后续组装逻辑（v2）与记忆管理功能（巩固/审计/待审）共同遵守的架构依据。

## 问题背景

2026-08-03 讨论「孤立文档」回答质量问题时暴露了更深层的结构问题：检索命中率低、启发式提取脆弱、`MEMORY.md` 时间线与 L2 正文之间断链。本模型把这些问题归因到记忆系统的职责边界不清，先立架构立场，再谈具体改造。

## 一、记忆统一模型：双层 MD = 唯一持久记忆载体

一切跨会话记忆都落双层 MD（或与它同构的纯文本文件），禁止在组装层另建记忆载体。按类型与生命周期划分：

| 记忆类型 | 载体 | 生命周期 | 索引方式 |
|---|---|---|---|
| 瞬时上下文（多轮对话）| 会话内存 `history` | 会话级，可 `/clear` | 无索引（用完即弃）|
| 规范（怎么做事）| L1 `KB/FRAMEWORK/RULES` | 长期 | 无需双链（规则非关联物）|
| 事实/知识 | L2 `notes/**` | 长期 | 双链 + grep + 图谱 |
| 经验/决策（时间线）| L1 `MEMORY.md` | 长期 | **应双链到相关 L2 文档**（现状缺失，见第四节）|
| 规划/任务 | `tasks.json`（结构化）| 进行态 | #id 引用文档 |
| sub-agent 记忆（预留）| `notes/agent-*/` | 随生命周期 | 同 L2 待遇 |

内核约定：
- **写入唯一路径**：LLM 写回块 → `pending/` → 人审批准 → 落 `notes/` 或 `MEMORY.md`；人工直接编辑始终允许（知识人写人读）。
- **组装只管读**：任何组装/检索改动不得绕过上述写入路径，不得新增记忆载体。

## 二、双链索引的边界：上下文要不要双链

- **瞬时上下文（多轮 history）：不要双链。** 它是会话内状态，不是可复用记忆。
- **持久化那一刻：要双链。** 记忆从「上下文」升级为「知识/经验」的转换点就是写回人审；落 `MEMORY.md` 时间线条目时，应同时链接它涉及的相关 L2 文档。

> **双链 = 记忆从上下文升级为知识的签名。**

双链服务于可复用记忆（L1 决策、L2 知识），不服务于瞬时上下文；上下文→双链的转换由写回环节完成，组装环节不负责制造链接。

## 三、分片/组装三条铁律

组装逻辑（把双层 MD 读进 LLM 上下文）必须与双层 MD 的**固有结构**与**管理功能**保持一致：

1. **不发明新分片元数据**。切分单位 = 双层 MD 既有结构：文件（FRAMEWORK）、`##` 小节（MEMORY 日期条目、FRAMEWORK 主题）、目录（notes/）。任何「按 XX 切」的工具（如 read_l1 按 `##` 返回）都是在尊重文件本体结构，LLM 看到的切片与文件本体一致，避免出现「组装视角」与「文件视角」两套世界。
2. **权威性 = 源文件**。`INDEX.md`、`memory_summary.md` 是派生产物（自动生成、无人审、可重建），只能做索引/摘要提示，**绝不替代原文**。检索/工具必须能回到源文件原文；与「人审只守源文件变更」的既有原则一致。
3. **写入与组装解耦**。同步/图谱/待审/巩固/审计等管理功能独立运行；组装改「读法」不得触碰管理功能，管理功能也不得依赖组装产物。

**会话上下文单独处理**：多轮 `history` 是组装逻辑里唯一非双层 MD 的部分，直接注入、不进工具、不读文件——把瞬时状态硬塞进长期记忆是反模式。

## 四、已知结构缺陷：记忆断链

`MEMORY.md` 时间线条目目前**不链接**到相关 L2 文档（例：修了托盘心跳 bug 的记忆，应链接到应用文档而不只是文字记录）。后果：
- 检索「心跳」撞不到应用文档 → 记忆（L1 时间线）与知识（L2 正文）断链；
- 「孤立文档」现象的另一半根因：不只是正文未链接，是记忆层本身孤立。

修复方向（单独立项，与组装逻辑无关）：写回块落 `MEMORY.md` 时自动生成到相关 L2 文档的 `[[双链]]`（可并入巩固器或写回环节做一次关联建议，人审确认）。

## 五、对后续决策的约束（v2 组装策略检查清单）

任何「上下文组装 v2」（把 L1/L2 读取从注入改为 LLM 工具取用）必须逐条对照：

- [ ] 不新增记忆载体，写入仍走待审→人审；
- [ ] 切分单位 = 文件 / `##` 小节 / 目录，不发明新元数据；
- [ ] 工具返回源文件原文（read_l1/search 等），派生产物仅作索引提示；
- [ ] 会话 `history` 保持直接注入，不进工具；
- [ ] 涉及规范/历史决策的问题，引导 LLM 先取 L1 原文再回答（规则层），不得凭模型知识陈述规范；
- [ ] 未配置 LLM 时降级回「注入 + 启发式预检索」，工具化只对有 LLM 会话生效；
- [ ] 管理功能（同步/图谱/待审/巩固/审计）不受组装改动影响。
