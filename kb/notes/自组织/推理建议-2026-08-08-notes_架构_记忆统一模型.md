# 读时推理建议

> 来源：`notes/架构/记忆统一模型.md` 被高频读取触发的 LLM 分析（派生产物，人工核对）


## 矛盾
- **记忆统一模型.md** vs **记忆统一模型.md**：文档内部冲突：开篇定调『双层 MD 是本系统唯一的持久记忆载体，禁止在组装层另建记忆载体』，但记忆分类表又把 tasks.json（结构化 JSON，非 MD 文本）列为『规划/任务』记忆的持久载体，未说明该非 MD 载体的例外依据，与『唯一』表述矛盾。
- **记忆统一模型.md** vs **托盘应用.md**：主文档规定 L0 快照（kb/sessions/）『不入图谱/不入 L2 检索』、派生产物『绝不替代原文』，但托盘应用实现的检索是 ignore 遍历 + grep crate 全树匹配，未定义对 sessions/ 目录与派生产物文件的排除规则——按现状实现检索会命中本应排除的流水与派生内容，违反铁律2与 L0 边界。
- **记忆统一模型.md** vs **记忆统一模型.md**：『写入唯一路径：LLM 写回块 → pending/ → 人审批准 → 落 notes/ 或 MEMORY.md』与 L0 提炼路线第①步『轻量快照直接写入 kb/sessions/（写文件）』并存：前者自称唯一路径且『不得绕过』，后者却由系统直接落盘、绕开 pending/人审，文档未明示 L0 快照是写入路径的例外。
- **记忆统一模型.md** vs **记忆统一模型.md**：目录书写大小写不一致：L0 快照用小写 kb/sessions/，L1 规范用大写 KB/FRAMEWORK/RULES；在大小写敏感文件系统上是两个不同根目录，组装/检索按路径匹配或排除时会互相失配。

## 盲区
- **检索排除规则（白名单/黑名单）**：铁律2要求派生产物『绝不替代原文』、L0 快照『不入 L2 检索』，但托盘应用描述的 ignore+grep 全树检索没有定义如何排除 INDEX.md、memory_summary.md 与 kb/sessions/；需补充检索白名单（仅 L1 源文件与 notes/**）或黑名单规则，否则两条约束无法落地。
- **tasks.json 作为记忆载体的例外界定**：『双层 MD=唯一持久记忆载体』与分类表将 tasks.json 列为规划/任务载体直接冲突；需明确结构化任务的例外地位、与 MD 的 #id 引用边界，以及任务结束后是否/如何沉淀进 MEMORY.md 或 L2。
- **双链生命周期维护（断链修复）**：文档已承认 MEMORY.md 时间线断链是结构缺陷、并把双链定义为知识签名，但未定义 L2 文档重命名/删除/合并时如何修复 MEMORY.md 及 L2 内的双链、审计如何检出坏链；否则修复后断链仍会复发。
- **L0 快照的触发与清理策略**：分类表仅写『长期（可清理）』、三步路线①称『可先做』，但未定义何时触发快照（会话结束/轮数阈值）、保留期限、清理方式与容量上限；直接落盘会导致 kb/sessions/ 无界增长。
- **记忆分层判定规则（规范/时间线/L2 知识）**：写入唯一路径只规定落 notes/ 或 MEMORY.md，但 LLM 写回块如何判定一条记忆应归入 RULES（规范）、MEMORY.md（经验/决策）还是 L2 正文（事实/知识）没有任何决策标准，写回归类会随时间漂移。
- **图谱的定义与构建维护**：L2 索引方式（双链+grep+图谱）与管理功能清单（同步/图谱/待审/巩固/审计）都提到『图谱』，但全文未定义图谱从哪来、如何由双链构建、何时更新与校验，它是本模型里唯一完全未定义的组件。
- **人审通道治理**：写入路径强依赖 pending/人审，但未定义谁审、按什么标准审、审核频率以及 pending 积压处理；且 L0 提炼路线②明确『复用 pending 人审通道』，人审会成为写入与提炼的公共吞吐瓶颈。

## 整合建议
- `INDEX.md、memory_summary.md`：两者都是自动生成、无人审、可重建的派生产物，用途同为『索引/摘要提示』且都『绝不替代原文』；合并为单一生成文件可减少派生视图碎片，让『派生产物只作提示』的规则落在单点，也降低组装层误读派生产物的风险。
- `FRAMEWORK.md、RULES.md`：记忆分类表把规范类记忆的载体写为『L1 KB/FRAMEWORK/RULES』，即把二者视为同一个规范载体；若两文件内容重叠（同为 L1 规范层），可合并为一个规范文件，避免规则分散在多个 L1 文档中导致『改规则要改多处』。
